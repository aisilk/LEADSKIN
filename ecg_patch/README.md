## 1. 配置と起動

### iPhone（本アプリ）
1. `ecg_patch_app.py` を **「この iPhone 内 > Pythonista 3」**（Pythonista 自身のフォルダ。名前を変えたコピーや「この iPhone 内」直下ではない）に置き、**Pythonista のファイル一覧から開いて**実行する（ファイル App から直接開かない：4.2 節、r17 No.13・規則 11）。
2. Pythonista で開いて ▶ 実行。起動中画面（SC1）に版・前回の動作記録が出て、3 秒後に BLE を開始します。
3. 初回は Bluetooth の使用許可を求められるので「許可」。
4. **模擬器と試験するとき**：模擬器を見つけると「パッチ模擬器を検出しました」と尋ねるので「受け入れる」（設定「模擬器を受け入れる」が ON になります。既定は OFF：6.4 節・20.2 節）。

### iPad／別の iPhone（パッチ模擬器）
1. `patch_emu.py` を Pythonista 3 に置いて ▶ 実行。
2. 画面上部に `ECGP-A1B2C3D4 [S2 装着確認待ち]`、広告名 `ECGP-A1B2C3D4~0100005A` が出れば準備完了。
3. ID は「ID 変更」で変えられます（`patch_emu_settings.json` に保存）。

> どちらも **Pythonista を前面に出したまま** にしてください（バックグラウンドでは BLE が止まります）。

## 2. iPhone アプリの画面と操作

| 画面 | 内容 |
|---|---|
| SC1 起動中 | 版、初期設定の手順、前回の動作記録（最後 25 行）と落ちた位置 |

| SC4 横向き | iPhone を横にすると表示。格子・波形・パッチの判定パネル（r10：アプリは R 波検出・判定をしない。本体 No.29）。「状態表示」でモード B（電極はがれ・動き・衝撃の背景帯、不整脈の赤帯、傾き） |
| SC5 異常通知 | 赤の通知枠、R-R／中央値／心拍、5 段の進み具合（通知受信→記録待ち→受信 %→保存→ACK）、「波形を見る」「閉じる」 |

操作の流れ（12 章）：パッチ（模擬器）の行の **「接続」** → 患者 ID（任意）→ 時刻同期 → 30 秒受信 → 保存 → ACK → 切断。
受信中は「中止」ボタンで STOP を送り、受信分を `_partial` で保存します。

## 6. 仕様書で決まっていない部分の実装上の判断（要確認）

付属 B（FW 仕様書）・付属 D（模擬器仕様）が手元にないため、次の点は仮に決めています。FW 側と合わせて確認してください。

| 項目 | この実装での扱い |
|---|---|
| Device Status の `state` | `2`＝S2（装着確認待ち）、`3`＝S3（計測中）、`5`＝S5（異常通知あり）、`6`＝S6（電源 OFF） |
| 広告の status バイト | bit0 時刻設定済み、bit1 未通知あり、bit2 電極異常 |
| Emulator Info（16B） | `<IBBBB8s`：device_id（uint32 LE）・ver・state・flags・rsv・`PATCHEMU` |
| イベント 32B の CRC | 先頭 30B の CRC16（CCITT-FALSE）。不一致は記録して続行 |
| WAITING の後 | パッチは記録が終わると Status（last_cmd=0x20・result=0）を送り、波形の送信を始める。アプリは波形の到着でも WAITING を解除する |
| 異常通知の切り出し | `[t−3840, t+3840)` の開始を 0.5 秒周期の境界にそろえる（`_meta.csv` の行 k ⇔ サンプル 128k を保つため）。検知位置は `_event.json` の `detect_index` に記録 |
| 時刻のあるページが 1 枚もない（装着確認で 8 ページすべて時刻設定前） | 10.3 節の基準ページ（SET_TIME 後の最初のページ）が届くまで最大 9 秒待ってから保存。届かなければ SET_TIME の時刻から推定して時刻の先頭に `~` |
| REQ_PAGES の結果 RANGE | 9.4 節どおり当該ページを飛ばす（`pages_missing` に記録）。電源投入より前を指す wave_start は模擬器側で切り詰める |
| ACK 後の切断 | 模擬器（iOS ペリフェラル）からは切断できないので、9.6 節どおり 5 秒後に iPhone から切断 |
| R 波検出（13.6 節） | 「2 点差分の絶対値の 16 点移動和・最初の 2 秒で学習・しきい値＝雑音＋(信号−雑音)/4・不応期 51 点・1/8 追従」を整数演算で実装。**r17 のソースが手元にないため FW（rr_detect.c）とのビット一致は未確認**。ゴールデンベクタ（vectors/）が届いたら A12-01 で照合し、必要なら r17 の関数に差し替えてください |
| パッケージ構成（5.2・5.8 節） | 配布形式の 1 ファイル（`ecg_patch_app.py`）で作成。各節の見出しに A01〜A20 を付けています |
| SC4 の 10 秒表示・スワイプ、拍の行タップ | 未実装（APP-Q10 の決定待ち） |
| スレッド構成（5.9 節） | 仕様書 5.9 節は「CoreBluetooth の全操作をメイン（UI）スレッド」としているが、r17 の実績（No.14）に合わせ **BLE の操作は作業スレッド**、メインスレッドは画面とデリゲート（値を取り出して渡すだけ）にした。仕様書 5.9 節の改訂が必要 |

## 7. 確認できていること・できていないこと

- PC 上：自動テスト 60 件と偽 iOS 試験 52 項目はすべて合格。偽 iOS 試験は r17 の規則（objc_util を実行時に使わない・デリゲートの中で BLE を操作しない・解放済みのオブジェクトを使わない）の違反も検出します（r1 はここで検出されます）。
